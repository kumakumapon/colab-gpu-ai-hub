# 入力・実行・成果物の境界

WSL2 のローカル MCP は、ユーザーが信頼するホストから stdio で起動します。入力用の `workspace` と成果物用の `results_dir` はユーザーが管理する絶対パスで設定できます。必要な入力だけをワークスペースに置き、個人情報や第三者の素材を Colab に送る前に、その転送と処理に必要な許可を確認してください。

| 境界 | 実装 |
|---|---|
| ローカル入力 | パスは正規の相対パスに限定します。トラバーサル、隠しパス、資格情報に使う名称、シンボリックリンク、非通常ファイルを拒否します。メディアの形式と容量を調べてから GPU を確保します。 |
| MCP | 入力スキーマ付きの高レベル操作だけを登録します。ユーザー入力は JSON やファイルとして渡し、実行ソースはリポジトリに登録されたワーカーが提供します。モデル ID はワーカーの許可リストで検証します。 |
| 転送と保存 | ダウンロードした ZIP の項目名、件数、サイズ、ファイル種別を検証し、宣言した成果物の SHA-256 と一致したものをジョブ別ディレクトリへ公開します。MCP 応答はパス参照を返します。 |
| 資源 | ワークスペース単位のファイルロックで同時実行を1件に制限します。入力、実行時間、出力に上限があり、停止の確認が残っている場合は次のジョブを保留します。 |
| OAuth とログ | Colab CLI の OAuth は Linux キーリングを利用します。アダプターや MCP は未加工の CLI 標準出力・標準エラー、認可コード、トークンをエラー結果に入れません。公開エラーは固定コードです。 |

公式 Colab CLI は自身の履歴やログを `~/.config/colab-cli/` に書きます。ジョブの一時的なランタイム資格情報を含む `.colab-cli/`、`.gpu-ai-jobs/`、入力と出力は非公開で管理し、ログを共有するときは関連するエラーコードと状態だけを抽出してください。利用者が書き込めるワークスペースにある台帳、CLI 状態、設定ファイルを第三者と共有すると、ローカル保護の前提が崩れます。

Git には認証情報、秘密鍵、個人メディア、モデル重みを含めないでください。`.gitignore` は通常の保存先とファイル形式を除外します。合成入力はテスト実行時に生成します。

動画レポート、文字起こし、OCR、画像生成、LLM 出力には元データ由来の情報や誤りが含まれ得ます。SAM 2.1 は指定対象の推定マスクを出力し、相対深度は物理距離の単位を持ちません。
